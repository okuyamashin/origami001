# 折り方の手順図：方針

記録日：2026年10月8日

おりがみの折り方を手順図で示すための方針をまとめる。この部分はまだ実装していない。決まったことと検討中のことを分けて書く。未決定事項は末尾にまとめる。

## 1. 決まったこと

### 紙のモデル

- 紙は、表と裏で色が違う正方形として扱う。
- 紙の厚みはないもの（無限に薄い）として扱う。
- 折った状態は、紙の重なり順（層順）を含めて表す。

### 対象にする作品

- 平面で完結する作品（うさぎ、かえるなど）に絞る。
- 立体的な作品は対象にしない。

### データの持ち方

- 1ステップごとに折り目を1本ずつ足していく。
- 各ステップの折った状態は、それぞれ独立した「作品」のデータとして持つ。

### 参考にしないもの

- Origami Simulator は層順を扱えないため、参考にしない。

## 2. 検討中のこと

以下は提案の段階で、まだ採用は決まっていない。

### 画像の作り方

紙芝居の絵は画像生成AIで作っているが、手順図は画像生成AIで直接描かせない案がある。

画像生成AIは、折り線の位置、層の重なり、前後のステップのつながりを正確に保てない。そのため、見た目は手順図らしくても、実際には折れない図になりやすい。

代わりに、次のように役割を分ける。

| 担当 | 役割 |
| --- | --- |
| AI | 手順を決まった書式のデータで書く。説明文も書く。 |
| プログラム | 紙の状態（面、層順、表裏）を計算し、手順図をSVGで描く。 |

プログラムが行う1回の折りの処理は次のとおり。

1. 折り線より片側にある面を、折り線で折り返す。
2. 折り返した面の層の順番を逆にして、反対側の上に重ねる。
3. 折り返した面の表と裏を入れ替える。

AIの書いたデータは、層の指定を間違えることが多い。描く前に、プログラムで実際に折れるかを確かめる。

### 図の書き方

一般的な折り図の記号（Yoshizawa–Randlett 方式）に合わせる。

| 記号 | 意味 |
| --- | --- |
| 破線 | 谷折り |
| 一点鎖線 | 山折り |
| 矢印 | 折る方向 |

表と裏は、それぞれの色で塗り分ける。

### 使えそうな既存のもの

| 名前 | 種類 | 使い道 |
| --- | --- | --- |
| Rabbit Ear | JavaScriptライブラリ | 平らに折る計算と層順の計算 |
| FOLD 形式 | データ形式 | 各ステップのデータの保存。面の重なり順を書ける。 |
| ORIPA | ツール | 展開図から折り上がりの層順を求める。検証に使う。 |

### 折り方の種類を増やす順番

折り方の種類によって、実装の難しさが違う。

| 折り方 | 難しさ | 使う作品の例 |
| --- | --- | --- |
| すべての層を1本の線で折る | 簡単 | ほぼすべて |
| 上の層だけ折る | 中くらい | かえる |
| 中割り折り | 難しい | かえる、つる |
| つぶし折り | 難しい | かえる、つる |

すべての層を折る操作と、上の層だけ折る操作を、最初に作る。中割り折りとつぶし折りは、その2つを組み合わせた操作として後から足す。

### つるの扱い

つるの最後の工程（つばさを広げる）は立体になるため、「平面で完結する作品」から少し外れる。ただし、その直前までは平らに折れる。

最後の1ステップだけを画像で補えば、つるも対象に入れられる。

## 3. 置き場所（決定）

紙芝居のデータ（`data/<選んだ順のおりがみ名>/`）とは分け、おりがみごとに置く。

```
data/origami/<おりがみ名>/
```

- おりがみ名は [adding-a-story.md](adding-a-story.md) の表と同じ綴りを使う（`rabbit`、`clane`、`frog`）。
- 折り方のデータと手順図は `data/origami/<おりがみ名>/steps/` に置く。ファイルの名前と書式は未定。
- ディレクトリ全体の構成は [origami-format.md](origami-format.md) を参照。
